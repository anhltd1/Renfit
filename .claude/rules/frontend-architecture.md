# Frontend Architecture & Conventions

## Stack & structure
- **Vite + React 18 + TypeScript**, functional components only.
- **Routing**: `react-router` 7 (`Routes`/`Route`/`useNavigate` in `frontend/src/app/App.tsx`).
  `useNavigation()` is a legacy compatibility shim backed by React Router — prefer
  `useNavigate`/`useLocation` directly in new code.
- **Pages** (routed): `LandingPage`, `LoginPage`, `SignupPage`, `AdminLoginPage`,
  `UserDashboardPage`, `AdminDashboardPage`. `/ai-coach`, `/booking`, `/profile` all redirect to
  `/dashboard` (those tabs live inside `UserDashboardPage`).
- **Dead code**: `DashboardPage.tsx`, `ProfilePage.tsx`, `BookingPage.tsx`, `AIChatPage.tsx` exist
  but are not routed — don't build on them; they're removal candidates.
- **Guards**: `AuthGuard` (customer), `AdminGuard` (trainer) wrap protected routes.
- **Session**: `lib/auth.ts` (customer + its `token`, localStorage) / `lib/adminAuth.ts` (trainer
  token, localStorage) — opaque session tokens, no JWT, no refresh layer. Member API calls go
  through `lib/api/memberFetch.ts` (adds `Authorization: Bearer`, sends a 401 back to `/login`);
  clearing either session also revokes it server-side.
- **API clients**: `lib/api/*.ts` — typed `fetch` wrappers per domain (auth, profile, bookings,
  admin, chat, notifications). One client per concern; normalize errors to Vietnamese messages.
- **Icons**: `lucide-react` only.

## Device-based rendering (in progress — see the `ai-dlc` skill)
The project is mid-way through introducing a **device-based rendering split**: a desktop UI tree
and a distinct native-like mobile UI tree, chosen by `useDevice()`/`DeviceProvider`
(`frontend/src/app/device/`), not just responsive CSS. Status:
- `app/device/resolveDevice.ts` — pure device-class resolution (viewport + pointer/hover +
  manual override), fully tested (fast-check + RTL). This is stable — reuse it, don't reimplement
  detection elsewhere or scatter raw `matchMedia` calls in components.
- `app/shared/primitives/` — the DESIGN.md-conformant primitive library (`Button`, `Card`, `Input`,
  `Modal`, `Sheet`, `Toast`, `Tabs`) shared by both trees. Use these instead of ad hoc markup for
  anything matching their role.
- `app/desktop/*` / `app/mobile/*` trees — **planned, not yet built** for most screens; existing
  pages/components still live at their pre-rebuild paths (e.g. `app/pages/UserDashboardPage.tsx`,
  `app/components/BookingCalendar.tsx`) until migrated unit by unit. Check
  `aidlc-docs/inception/application-design/unit-of-work.md` for the current unit and don't
  assume a screen has been migrated unless its unit is marked complete in
  `aidlc-docs/aidlc-state.md`.
- Rule: `shared/*` must never import from `desktop/*` or `mobile/*`; `desktop/*` and `mobile/*`
  must never import each other. Cross-tree reuse only via `shared/*`.
- Routes stay the same for both devices — the tree is swapped internally by `useDevice()`, not by
  separate `/m/...` paths.

## State & hooks
- `useState` for local UI state (inputs, modals, step index).
- Extract a hook (`hooks/useX.ts`) once logic exceeds ~40 lines or is reused across components.
- Prefer controlled inputs (`value` + `onChange`).
- Data-fetching hooks (in progress, U2 of the rebuild) wrap `lib/api/*` so both device trees share
  identical request/response logic — don't call `lib/api` directly from leaf components once a
  shared hook exists for that concern.

## Styling
See `.claude/rules/design-system.md` for the full DESIGN.md-derived rules (colors, spacing, components,
accessibility). Quick reminders specific to frontend code structure:
- Tokens live in `frontend/src/styles/theme.css` (`:root` custom properties + Tailwind `@theme`).
  There is exactly **one** theme (dark) — no `.dark` class variant; don't reintroduce one.
- Use the `cn()` helper (`app/shared/primitives/cn.ts`, wraps `clsx` + `tailwind-merge`) when
  composing conditional class names instead of manual string concatenation.

## Testing (Vitest + RTL + fast-check)
See `.claude/rules/testing-conventions.md`. Test files are colocated (`Component.test.tsx` next to
`Component.tsx`), not in a separate `__tests__/` tree.

## PWA
`frontend/public/manifest.webmanifest` + `service-worker.js` + `lib/registerServiceWorker.ts`.
**Never** let the service worker cache `/api/*` or `/chat` — those must always hit the network.
Icons generated by `frontend/scripts/generate-pwa-icons.py` from `src/imports/image.png`.

## Verification
Run `npm run build` after any change (no separate typecheck script exists) and `npm run test` for
unit/property tests. Clean up `dist/` after ad hoc verification builds — it's gitignored but don't
leave build artifacts lying around during a session.
